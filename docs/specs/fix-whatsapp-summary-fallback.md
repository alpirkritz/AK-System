# Spec — Fix WhatsApp summary "system busy" fallback

Slug: `fix-whatsapp-summary-fallback`
Stack: `next-trpc-monorepo` (Next.js + tRPC + Drizzle)
Type: Bugfix

## Problem

On WhatsApp, every summary request ("סיכום קבוצות", "מה חדש") returns:

> "המערכת עמוסה כרגע ולא הצלחתי לסכם את הקבוצות. אנא נסה שוב מאוחר יותר."

This exact text is **not** in the codebase or git history — it is generated by the Hugo
agent (Gemini) when the `summarize_whatsapp_groups` tool returns a failure result and the
model paraphrases it as a generic "system busy" apology.

### Root cause

The `summarize_whatsapp_groups` tool (`apps/web/src/lib/conversation-engine.ts`) calls
`whatsapp.summaries.trigger`, which depends on the **live WhatsApp bridge**:

```
tool → whatsapp.summaries.trigger → bridge /groups/summarize-all
     → bridge posts back to /group-summary → Gemini → separate WhatsApp message
```

This path fails whenever the bridge is disconnected or its in-memory buffer is empty
(e.g. after a restart), and delivers results as *separate* messages rather than inline.
Every failure surfaces to the user as the vague apology.

The codebase already has a **robust DB-based path** that does not depend on the live
bridge and returns the summary text **inline**:

- `whatsapp.insights.digest` — prioritized cross-group briefing over persisted
  `whatsappMessages` (used by the `whatsapp_now` tool).
- `whatsapp.insights.forGroup` — per-group summary over persisted messages (used by the
  `whatsapp_group_insights` tool).

## Change

Repoint `summarize_whatsapp_groups` to the DB-based insights procedures so a real
summary is produced inline, independent of bridge/buffer state.

- No `groupJid` → `whatsapp.insights.digest({ window })`, return `text` inline.
- With `groupJid` → `whatsapp.insights.forGroup({ groupJid, window, mode: 'summary' })`,
  return `text` inline.
- Accept an optional `window` param (`6h` | `24h` | `7d`, default `24h`).
- Honest empty-state text already exists in those procedures
  ("אין קבוצות פעילות במעקב", "אין פעילות חדשה בקבוצות שאתה עוקב אחריהן בטווח הזה") — no
  more "המערכת עמוסה".

Update prompt guidance so Hugo delivers the summary inline and no longer treats this tool
as an async "separate WhatsApp messages" exception:

- `apps/web/src/lib/gemini-agent-engine.ts` (Hugo system prompt lines re: summarize tool).
- `apps/web/src/lib/conversation-engine.ts` (base system instruction + tool description).

## Out of scope

- Fixing/redeploying the production WhatsApp bridge (tracked separately).
- Rotating the exposed `GEMINI_API_KEY` (tracked separately; the key format `AQ.` looks
  like an OAuth token rather than an AI Studio `AIza…` key).

## Files

- `apps/web/src/lib/conversation-engine.ts` — tool handler + tool declaration + prompt line.
- `apps/web/src/lib/gemini-agent-engine.ts` — Hugo prompt lines.
- `apps/web/src/lib/whatsapp-bot.test.ts` — add coverage for the new tool routing (or a
  focused conversation-engine test).

## Acceptance criteria

- A summary request with no watched-group activity returns a clear "no new activity"
  message inline — never "המערכת עמוסה".
- A summary request with stored activity returns a real inline summary without depending
  on the live bridge.
- Single-group requests (`groupJid`) return an inline per-group summary.
- Lint + web build pass.
