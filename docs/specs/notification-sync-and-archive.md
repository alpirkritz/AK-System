# Notification sync & archive correctness

## Goal

התראות מתנהגות היום כאילו הארכוב לא נשמר ושהאפליקציה והווב לא מסכימות ביניהן. בפועל הארכוב **כן** נשמר בבסיס הנתונים — מה שלא עובד הוא שכבת ההצגה: ההתראה שכבר הוצגה במגש של המכשיר לא מבוטלת לעולם, כל ההתראות חולקות `tag` אחד, וכפתור "ארכיון" שעל ההתראה בווב נכשל בשקט. המטרה: מצב ההתראה במסד הנתונים הוא מקור האמת היחיד, וכל משטח (ווב, אפליקציה, מגש ההתראות של המכשיר) מתיישר אליו.

## Root causes (אומתו בפרודקשן על EC2)

| # | שורש | עדות |
|---|---|---|
| A | כפתור "ארכיון" על התראת ווב שולח POST ל-`/api/trpc/notifications.archive` עם `{id}` בלי מעטפת superjson שה-tRPC דורש | `POST` מתוך EC2 החזיר `400 BAD_REQUEST` — `invalid_type, expected object, received undefined`. ה-`.catch` תופס רק שגיאות רשת ולכן 400 נכשל בשקט בלי אפילו ה-fallback שנועד לו |
| B | כל ההתראות מוצגות עם `tag: 'ak-push'` ו-`renotify: true` | `apps/web/src/sw.ts:101-102`. כל דחיפה חדשה **מחליפה** את הקודמת במגש — רק האחרונה נראית, והשאר נעלמות מהמגש אך נשארות לא-נקראות במסד |
| C | אין פיוס בין מצב השרת למגש ההתראות | ארכוב בווב או באפליקציה לא סוגר את ההתראה שכבר הוצגה. באפליקציה `dismissNotificationAsync` נקרא רק כשלוחצים "ארכיון" על ההתראה עצמה (`apps/mobile/lib/notifications.ts:55`) |
| D | דף ההתראות בווב לא מרענן מעצמו | `apps/web/src/app/notifications/page.tsx:185` — `useQuery` בלי `refetchInterval`, ריענון רק אחרי מוטציה מקומית. ארכוב מהטלפון לא משתקף בווב עד רענון ידני |

מצב הנתונים בפרודקשן שאימת שהכתיבה עצמה תקינה: 5978 התראות, 5976 בארכיון, 2 בתיבה.

## User stories

1. כשאני מארכב התראה בווב, היא נעלמת גם מהמגש של הטלפון ושל הדפדפן — לא חוזרת.
2. כשאני מארכב התראה באפליקציה, הווב מתיישר תוך שניות בלי שארענן.
3. כשמגיעות שלוש התראות שונות, אני רואה שלוש במגש — לא אחת שדורסת את השאר.
4. כשאני לוחץ "ארכיון" ישירות על ההתראה, זה באמת מארכב.
5. התראה שכבר קראתי או ארכבתי לא מתריעה עליי שוב.

## Acceptance criteria

- [ ] כפתור "ארכיון" שעל ההתראה בווב מארכב בהצלחה — תשובת 200, והשורה ב-`notifications` מקבלת `archived_at`.
- [ ] כל התראה מוצגת עם `tag` ייחודי משלה, כך ששתי התראות שונות לא דורסות אחת את השנייה.
- [ ] `renotify` כבוי — עדכון של התראה קיימת לא מתריע שוב.
- [ ] ארכוב או סימון-כנקרא בווב סוגר את ההתראה המתאימה במגש הדפדפן.
- [ ] ארכוב באפליקציה סוגר את ההתראה המתאימה במגש של מערכת ההפעלה.
- [ ] דף ההתראות בווב מתרענן לבד (מרווח קצוב וגם בחזרת פוקוס), כך שפעולה מהטלפון משתקפת בלי רענון ידני.
- [ ] כשהדפדפן חוזר לפוקוס, התראות במגש ששייכות לרשומות שכבר מסומנות כארכיון נסגרות.
- [ ] אין רגרסיה: ארכוב וביטול-ארכוב מתוך ממשק הווב והאפליקציה ממשיכים לעבוד, כולל `archiveAll` וה-undo שלו.

## API shape

אין procedure חדש. שינוי אחד בחוזה הקריאה מתוך ה-service worker: במקום POST גולמי ל-`/api/trpc/notifications.archive` הוא יקרא ל-`PATCH /api/notifications` עם `{ id, action: 'archive' }` — אותו חוזה REST שהאפליקציה כבר משתמשת בו (`apps/mobile/lib/api.ts:375`) ושנתמך ב-`apps/web/src/app/api/notifications/route.ts:87`. זה מונע מה-SW להתחזות ללקוח tRPC עם superjson.

ערוץ הודעות חדש בין הדף ל-service worker:

```ts
// page → sw
{ type: 'CLOSE_NOTIFICATIONS', notificationIds: string[] }
```

## UI surface

- `apps/web/src/sw.ts` — tag ייחודי לכל התראה, `renotify: false`, תיקון קריאת הארכוב, מאזין ל-`CLOSE_NOTIFICATIONS`.
- `apps/web/src/app/notifications/page.tsx` — `refetchInterval` + `refetchOnWindowFocus`, ושליחת `CLOSE_NOTIFICATIONS` ל-SW אחרי ארכוב או סימון-כנקרא.
- `apps/mobile/app/notifications.tsx` + `apps/mobile/lib/notifications.ts` — סגירת ההתראה במגש כשמארכבים מתוך האפליקציה, לפי התאמת `data.notificationId`.

אין רכיבים חדשים ואין שינוי עיצובי — ולכן אין שער UI designer. הטקסט היחיד שנוגעים בו הוא התווית הקיימת "ארכיון" על ההתראה, שנשארת כפי שהיא.
